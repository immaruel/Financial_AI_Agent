Persnoal User Memory Retrieval Logic

저장된 모든 메모리를 다 쓰지 않고, 질의와 관련성이 높은 일부만 골라 context로 입력

01
태그 매칭 점수 계산

질의에서 뽑아낸 entity, industry, intent가 메모리에 붙은 태그와 겹치는지 하나씩 확인하고, 겹치는 요인마다 정해진 가중치를 더합니다. 예를 들어 entity 일치와 industry 일치가 동시에 되면 두 가중치를 합산해 점수가 더 높아집니다

02
태그 없는 메모리는 어휘 중복도로 대체

태그가 하나도 없는 메모리는 태그 비교를 할 수 없으므로, 대신 메모리 content 텍스트와 질의 원문이 얼마나 같은 단어를 쓰는지를 세어 그 중복도를 점수로 사용합니다

03
최소 점수 미달 후보 제외

1, 2단계에서 계산한 점수가 정해진 최소 기준(min_rule_score)을 넘지 못하면, 질의와 관련이 있다고 보기 어렵다고 판단해 후보에서 제외합니다

04
유효 기간과 최신 버전 확인

유효 기간을 벗어났거나, 더 최신 내용으로 덮어써져 superseded_by가 채워진 메모리는 오래되었거나 무효한 정보이므로 후보에서 제외합니다

05
점수 내림차순 정렬

3, 4단계를 통과해 남은 후보들을 점수가 높은 순서대로 줄 세워, 질의와 가장 관련성이 높은 메모리가 앞에 오도록 합니다

06
메모리 개수와 토큰 budget 안에서 최종 선택

정렬된 순서대로 메모리를 하나씩 담되, 미리 정해둔 최대 메모리 개수 또는 토큰 budget 중 하나라도 초과하는 순간 멈추고, 그때까지 담긴 메모리만 context에 입력합니다

선택 예시

질의: "삼성전자 반도체 부문 실적 어떻게 생각해?" (Entity: 삼성전자, Industry: 반도체)

저장된 메모리 태그 질의와의 관련성 결과
투자 성향: 보수적 Entity 삼성전자, Industry 반도체 Entity 일치 + Industry 일치 → 가중합 점수 높음 선택
관심 테마: 배당주 태그 없음 질의 원문과 단어 중복도 낮음 제외

금융 특화 오류 분류 체계

금융 AI가 만들 수 있는 8가지 실패 유형을 사전 정의하고, 각 단계에서 감지합니다

F1 엔티티 혼동

현대차 ≠ 현대모비스
계열사/본사 혼동, ticker mismatch

F2 시간축 오류

발표일 ≠ 효력일
최신 정보 대신 과거 정보 사용

F3 숫자 오류

절대값 ≠ 증감률
금액/비율/단위 오류

F4 이벤트 귀속

주체 기업 ≠ 대상 기업
행위자와 영향받는 기업 뒤바뀜

F5 근거 누락

핵심 citation 부족
반대 evidence 누락

F6 추론 과장

상관관계 → 인과 단정
가능성을 사실처럼 표현

F7 안전성 오류

투자 권유, 과도한 확신
리스크 경고 누락

F8 과잉 방어

답할 수 있는 질문도 회피

QUERY TYPES

질의 유형과 검색 경로

Q: "정부의 전기차 보조금 축소가 완성차 기업과 배터리 기업에 어떤 경로로 영향을 미쳤는가?"
정책 → 산업 → 기업 관계 질문 → Graph Retrieval Worker → 관계 경로 탐색 → 경로 상의 근거로 답변 구성
Multi-hop Reasoing을 요구하는 질문입니다. 그래프에서 정책, 산업, 기업이 실제로 어떻게 연결되어 있는지 경로를 따라가며 확인합니다.
Q: "메타의 경영진은 매출 둔화 원인을 어떻게 설명했나?"
경영진 발언 원문 필요 → Hybrid Retrieval Worker → 관련 문단 검색 → 원문 인용 기반 답변
경영진 발언처럼 원문 자체가 핵심 근거인 질문입니다. 관계 탐색보다 실제 텍스트를 찾아 인용하는 것이 중요합니다.
Q: "이번 반도체 레버리지 ETF 정책으로 인해 수혜를 보거나 영향을 받는 주요 산업과 기업은 어디인가?"
관계 탐색과 원문 확인 모두 필요 → Graph + Hybrid Retrieval Worker → Evidence Fusion(Rerank) → 두 결과를 기반으로한 답변 구성
정책이 산업과 기업으로 퍼지는 관계, 그리고 그 관계를 뒷받침하는 원문 근거가 모두 필요한 복합 질문입니다. 두 검색 경로가 함께 실행되어 결과를 합칩니다.

WHY

왜 만들었는가

01

일반 RAG로 금융 질문을 던져보았습니다

기업 혼동, 시간 오류, 근거 없는 인과 추론 — 금융 도메인에서 텍스트 기반 RAG는 예상보다 자주 틀렸고, 왜 틀렸는지 추적할 방법이 없었습니다.

02

지식 그래프 위에 멀티 에이전트 오케스트레이션을 설계했습니다

질의 이해 → 라우팅 → 병렬 검색 → 답변 생성 → 검증 → Critic/Supervisor 복구로 이어지는 멀티 에이전트 흐름을 설계했습니다.

03

AI가 틀리는 것보다, 왜 틀렸는지 모르는 것이 더 위험합니다

이 시스템의 핵심은 "틀리지 않는 AI"가 아닙니다. 실패를 감지하고, 분류하고, 스스로 복구하거나, 적절한 시점에 인간에게 넘기는 것입니다.
